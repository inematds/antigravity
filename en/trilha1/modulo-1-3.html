⬇️ Install AntiGravity

The simplest concrete first step is to download the AntiGravity from the official site — antigravity.google — and install it like any other application on your computer.

🧭 Main concept

There’s no secret here. It’s a program that runs on your machine, like a text editor or a browser. Download it from the official source, open the installer, and follow the steps.

  • •Go to the official site (antigravity.google)—avoid third-party links.
  • •Download the version for your system (Windows, macOS, or Linux).
  • •Install and open it — it’s the same workflow as any app.

⚙️ Install Node.js

O Node.js is the “engine” that lets AI create and run projects at your computer’s level. Download it from nodejs.org. Without it, most apps simply won't run locally.

✓ With Node.js installed

  • ✓AI can run the project on your machine
  • ✓You install app dependencies
  • ✓localhost works as usual

✗ Without Node.js

  • ✗Most apps don’t start locally
  • ✗Installation commands fail
  • ✗You get stuck on the very first project

💡 Practical tip

On nodejs.org, choose the version LTS (long-term support): it’s the most stable and recommended for most people. After installing, just reopen AntiGravity.

🐙 GitHub: Repositories

O GitHub is where project files are stored and versioned. Each project lives in a repository (or “repo”). That’s where you import ready-made code from—and where you’ll publish your own later.

🌍 Public repository

  • •Anyone can view and import
  • •Great for templates and examples
  • •You can learn a lot by reading open-source code

🔒 Private Repository

  • •Only you (and anyone you invite) can access it
  • •Ideal for your own projects or clients’ projects
  • •Same structure, restricted visibility

🟢 The green "Code" button

In any repository, the green button "Code" reveals the Repo URL. This is the URL you'll paste into AntiGravity to import the project. Remember this reflex: "Code" → copy URL.

📥 Import Project + Localhost

With the repo URL in hand, the process is straightforward: you paste the URL and ask the agent to import it. Then ask it to run, and the project runs at a local address (localhost:porta) that only you can see.

1

Bring in the code

Paste the repository URL and ask the agent to import the project to your machine.

2

Run

Ask the agent to start the project. It installs what’s needed and gets things going.

3

View on screen

It runs at a local address, like localhost:3000. Open it in your browser and see the app working — only on your machine.

🌐 What is “localhost”

"localhost" is your own computer acting as a server. The door (e.g., 3000, 5173) is just the "channel" where the app is listening. It's a private address: nobody on the internet can see it, only you.

⌨️ The terminal / CLI

O terminal (also called CLI, or “command-line interface”) is how you talk to the computer by text, instead of clicks. Many actions—installing things, running commands, building—happen there.

examples of terminal commands
npm install      # instala o que o projeto precisa
npm run dev      # roda o projeto em modo de desenvolvimento
node --version   # mostra a versão do Node.js instalada

The good news: in the agentic workflow, most of the time it’s the agent who types these commands for you. But understanding that the terminal exists—and that it’s just “the computer listening to text”—takes away the fear when you need to paste a command manually.

💡 Practical tip

Don’t memorize commands. When you need one, ask the agent: "what command should I run for [goal]?" The terminal stops being intimidating when you treat it as just another channel for conversation.

🖥️ The interface

It’s worth getting to know the four main areas of the screen. You don’t need to memorize anything — just know where everything is so you don’t get lost when you start building.

1

Where you talk to the agent and ask for what you want. It’s the heart of the workflow.

🌐 Browser control + self-correction

This is the game-changing resource: the agent opens the browser, clicks buttons, checks the result on screen, and self-corrects — without needing plugins. It “sees” what happened and adjusts on its own.

In practice, this saves a lot of back-and-forth: instead of testing, copying the error, pasting it back, and asking for a fix, the agent closes that loop on its own. You describe it, and it builds, checks, and fixes it.

🔬 Practical example

Let’s bring it all together in one gesture. Import a landing page template from a public repository and run it on localhost:

  • 1.Get the URL of a public repo with a simple landing page template.
  • 2.Paste it into AntiGravity and ask it to import; then ask it to run.
  • 3.Open the local address (e.g., localhost:3000) and view the site on your machine.

In just a few minutes, you go from zero to a site running locally — without writing a single line by hand.

🏋️ Exercise

Get your environment truly ready. Complete the full workflow:

  1. Install the AntiGravity (from antigravity.google) and the Node.js (from nodejs.org, LTS version).
  2. Import a any public repository (a simple template will do).
  3. Run in the localhost e note the port that appeared (e.g., 3000, 5173).

If you saw the app open in the browser, your environment is ready for Track 2 — where we'll build the first app from scratch.
