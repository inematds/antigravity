✈️ CODA & Claude Code

The professional framework for coding with AI: separate the IDE (the fighter jet) from the model (the pilot), and work through the five stages — Configure, Outline, Deploy, Automation, Review.

What it is:

The IDE (AntiGravity, Cursor) is the plane; the model (Claude Code, Gemini) is the pilot. You switch pilots depending on the mission.

Why learn:

Understanding this separation gives you freedom: the skill isn’t tied to a tool or a model.

Key concepts:

Tool vs. model · pilot swap · preflight checklist.

What it is:

A context file (claude.md / Gemini.md) in EVERY project: tech stack, directories, commands and — most importantly — success criteria + how to test.

Why learn:

It's the backbone of the project, a living document that helps the AI get things right without you having to repeat everything.

Key concepts:

Context · success criteria · living document.

What it is:

Define the problem and success BEFORE writing code. Back-and-forth conversation, clarifying questions, “ultrathink” for deep reasoning.

Why learn:

Spending ~95% of the time on the plan avoids rework and code that solves the wrong problem.

Key concepts:

Plan Mode · specification · ultrathink.

What it is:

Run multiple agents at the same time (5–7), from the terminal or IDE. You can even use web agents connected to a repo, running with your laptop closed.

Why learn:

Parallelizing multiplies your output — several problems move forward at once.

Key concepts:

Parallelism · web agents · throughput.

What it is:

Create specialized subagents, one per subtask (e.g., title, intro, script). Each has its own context window.

Why learn:

Splitting work among subagents prevents context overflow and keeps each task focused.

Key concepts:

Subagent · context window · specialization.

What it is:

Explicit success criteria (in claude.md): runs without errors, tests pass, no lint warnings, fulfills the request, changes are explainable. Ask for a review as a "skeptical senior engineer".

Why learn:

Without clear criteria, "done" becomes a matter of opinion. Verification is what separates amateurs from professionals.

Key concepts:

Success criteria · verification · skeptical review.

What it is:

Sometimes a short prompt works better than a super-detailed one. Try the short one first and see if the AI gets it right on its own.

Why learn:

Too many instructions can confuse the model. Simplicity saves time and tokens.

Key concepts:

Brevity · iteration · letting AI infer.

🧰 Skills & Prompts Library

Seven ready-to-download artifacts to adapt: cloning and conversion skills, a debug prompt, an MCP config, a claude.md template, a QA checklist, and the prompt collection.

What it is:

A protocol that rebrands a template: logo, copy, brands, prices, reviews, and color.

Why learn:

Reuses a validated structure for a new niche in minutes.

Key concepts:

Template · rebrand · replacement checklist.

What it is:

Converts a framework-based website into a single self-contained HTML file, ready to paste into GoHighLevel or WordPress.

Why learn:

Lets you deliver where the client already is, without starting over from scratch.

Key concepts:

Self-contained · inline · portability.

What it is:

A structured template (XML) for debugging with AI: generates predictions, investigates, finds the root cause, and gives step-by-step instructions. (Third-party open-source tool.)

Why learn:

Turns “it’s showing an error” into a disciplined troubleshooting process.

Key concepts:

Prediction · root cause · step-by-step.

What it is:

Ready-to-use MCP configuration (n8n, Notion, Pinecone, Supabase, Vercel, Fireflies) with key placeholders.

Why learn:

Connects your agent to external tools without setting everything up by hand.

Key concepts:

MCP · servers · keys/placeholders.

What it is:

The CODA context file template: tech stack, directories, commands, success criteria + how to test.

Why learn:

It's the starting point for the "C" in Configure in any new project.

Key concepts:

Context · stack · success + testing.

What it is:

A phased QA and stress-testing protocol that classifies each finding as Critical / Warning / OK.

Why learn:

Ensures you publish only after checking what matters — before "taking off".

Key concepts:

QA · severity · pre-publication.

What it is:

A collection: problem→SOP, Plan Mode, research→research.md, design inspiration, review/verify, screenshot-based troubleshooting, connecting MCP, env var, and “less is more.”

Why learn:

It’s your Swiss Army knife: copy, paste, and adapt it for any CODA step.

Key concepts:

Reuse · SOP · living library.
