🧩 Llevar sitios a GoHighLevel/WordPress

Los sitios creados con frameworks no se pueden integrar directamente en constructores visuales. La solución: una skill que convierte el codebase en un único HTML self-contained que puedes pegar en el bloque "Custom HTML/JS" de GHL o WordPress, y ajustar lo que no funcione.

🧩 El problema

Construiste un sitio increíble en un framework (React, Next, Vue, Svelte). Entonces el cliente dice: "uso GoHighLevel" (o WordPress). El problema: estos constructores son "arrastrar y soltar" e no aceptan directamente un codebase de framework. Es un desajuste de lenguaje.

✓ Lo que tienes

  • ✓Sitio en React / Next / Vue / Svelte
  • ✓Varios archivos, componentes, build
  • ✓Funciona de maravilla en localhost

✗ Lo que acepta el constructor

  • ✗Bloques visuales de «arrastrar y soltar»
  • ✗No entiende los componentes ni el proceso de build
  • ✗Pega el framework sin modificar → se rompe

💡 La idea

El camino no es abandonar el framework, sino traducir el resultado a un formato que el constructor entienda. De eso trata el resto del módulo.

🔄 Una Transformer Skill

La traducción se realiza mediante una Transformer Skill: una skill que toma todo el codebase y lo convierte en un único archivo HTML autocontenido — todo en un solo lugar (HTML + CSS + JS), compatible con el bloque «Custom HTML/JS» de GHL.

💡 Consejo práctico

La Transformer Skill también está en la Biblioteca (Ruta 5). Úsala como punto de partida y prueba el HTML antes de entregárselo al cliente.

🚫 Restricciones del bloque Custom HTML

El bloque "Custom HTML/JS" es potente, pero tiene reglas claras. Conocerlas es lo que hace que la conversión funcione a la primera. En resumen: nada de herramientas de frameworks, solo lo básico de la web.

✗ No puede

  • ✗JSX / Babel
  • ✗ES modules (import / export)
  • ✗Herramientas de build (Vite / Webpack)
  • ✗APIs de Node (process.env)
  • ✗Etiquetas html / head / body (GHL inyecta el shell)

✓ Puede

  • ✓HTML + style + script vanilla
  • ✓SVG inline
  • ✓CDN (scripts externos por URL)
  • ✓Tailwind vía CDN
  • ✓Prefijar las clases CSS para evitar conflictos

⚠️ Trampa común

Olvidar prefijar las clases. El constructor tiene su propio CSS; si tus clases tienen nombres genéricos, entran en conflicto y el diseño se rompe. Usa prefijos (p. ej., vf-) y mantente a salvo.

🎬 Creación «design-first» en AI Studio

Un flujo que da un resultado más atractivo: construye primero en una plataforma enfocada en diseño (un AI Studio de diseño), descarga el archivo y después clon en AntiGravity y conviértelo. Este camino cubre ~99% de los sitios — solo algunas animaciones muy específicas podrían no funcionar.

1

Construye en AI Studio (design-first)

Concéntrate en lo visual en una plataforma de diseño: ahí el sitio se ve bonito más rápido.

2

Descárgalo y clónalo en AntiGravity

Lleva el archivo al entorno local, donde tienes control total.

3

Convierte a 1 HTML

Ejecuta Transformer Skill y genera el archivo self-contained. Cubre ~99% de los casos.

💡 Por qué design-first

Empezar por el diseño da un sitio más atractivo antes de la parte técnica. La conversión viene después, sobre una base que ya le gusta al cliente.

✂️ HTML Sniping

No siempre quieres migrar la página completa. A veces el cliente ya tiene una página en GHL/WordPress y solo quiere una sección más atractiva. Ahí entra el HTML Sniping: en vez de migrarlo todo, inyectas bloques premium puntuales de HTML de alta calidad dentro de la página existente.

Migración completa

Toda la página se convierte en 1 HTML self-contained.

Cuándo: el sitio es nuevo o se rehízo por completo.

HTML Sniping

Un bloque premium puntual se integra en una página que ya existe.

Cuándo: solo una sección necesita una mejora.

💡 Consejo práctico

Sniping es quirúrgico: genera valor visual sin tocar el resto. Ideal para "hacer más atractiva esta sección" sin rehacer toda la página.

📋 Pegar en GHL y ajustar

Con el HTML a mano, el paso final es mecánico. En el editor de GHL: agrega un bloque "Custom Code" → pega el HTML → guarda/publica → prueba. Si se rompe en el móvil, vuelve al agente, pídele que lo corrija, vuelve a copiar y pegar.

1

Agrega "Custom Code"

En el editor, arrastra el bloque de código personalizado hasta donde debe aparecer la sección.

2

Pega, guarda y publica

Pega el HTML autocontenido, guarda y publica la página.

3

Prueba, también en el móvil

Revísalo en la computadora y en el celular. ¿Se rompió en el celular? Ve al paso 4.

4

Repara y vuelve a pegar

Dile al agente «en el móvil haz X, corrígelo». Toma el nuevo HTML, vuelve a copiarlo y pégalo.

⚠️ El ciclo de ajustes

En móvil es donde más se rompe. Trátalo como un ciclo corto: describe el problema → corrige → vuelve a copiar → vuelve a pegar → prueba. Repite hasta que quede perfecto en ambos tamaños.

🔬 Ejemplo práctico

Tienes un sitio en React de un taller mecánico y el cliente usa GoHighLevel. El camino:

  1. Ejecuta Transformer Skill: el codebase React se convierte en 1 HTML autocontenido (sin importación/exportación, sin build, con clases prefijadas).
  2. En GHL, agrega un bloque Custom Code, pega el HTML, guárdalo y publícalo.
  3. Ábrelo en el celular: la sección de precios se está desbordando del ancho.
  4. Vuelve al agente: "en mobile la tabla de precios se desborda; corrígelo manteniendo el HTML único". Vuelve a copiar y pegar.

Resultado: el sitio React del cliente funciona dentro de GoHighLevel, sin problemas en escritorio y en móvil.

🏋️ Ejercicio

Convierte un sitio (hecho antes) a 1 HTML autocontenido y pega en un bloque Custom Code de GHL o WordPress:

  1. Busca un sitio tuyo de la Trilha 2 (o un clon de la Trilha 3.1).
  2. Ejecuta Transformer Skill y genera el HTML único, respetando todas las restricciones.
  3. Pega en un bloque Custom Code de GHL o WordPress, guarda y publica.
  4. Prueba en el móvil y ejecuta el ciclo de ajustes hasta que quede perfecto.

Meta: un sitio de un framework funcionando dentro de un constructor visual, sin romperse.
