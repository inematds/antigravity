🧬 Cloning Skill

A Cloning Skill es un protocolo que toma un template validado y lo re-marcar para un nuevo cliente o nicho: cambia el logo, el copy, las marcas, los precios, las reseñas y el color de acento, sin rehacer la estructura desde cero.

✓ Cuándo usar

  • ✓Ya tienes una plantilla que funciona
  • ✓Necesita atender a varios clientes similares
  • ✓Quieres mantener la estructura y solo cambiar la marca

✗ Cuándo evitarlo

  • ✗El nuevo proyecto tiene una estructura diferente
  • ✗Todavía no validaste la plantilla original
  • ✗El contenido cambia más que la marca
cloning-protocol.md

protocolo de clonación / rebranding

⬇️ Descargar skill
uso rápido
Use a Cloning Skill neste template. Re-marque para o cliente abaixo,
trocando: logo, copy, nome de marca, preços, avaliações e cor de acento.
Mantenha a estrutura intacta.

Cliente: [nome] · nicho: [nicho] · cor: [hex]

🔄 Transformer Skill

A Transformer Skill convierte un sitio hecho con un framework en un único HTML autocontenido — todo integrado (CSS y JS inline), listo para pegar dentro de plataformas como GoHighLevel o WordPress.

📦 Entregar donde ya está el cliente

Muchos clientes ya tienen su sitio en GoHighLevel o WordPress. En vez de migrarlo todo, conviertes tu página en un único bloque y lo pegas allí. Un archivo, cero dependencias externas.

framework → HTML autocontenido

self-contained (CSS e JS inline, sem dependências externas),
pronto para colar dentro do GoHighLevel/WordPress.

🐞 Prompt de Ultimate Debugger

O Ultimate Debugger Prompt es un template estructurado (en XML) para depurar errores con IA de forma disciplinada: el modelo genera predicciones, investiga, encuentra la causa raíz y da instrucciones paso a paso. Es una herramienta de código abierto de terceros.

1

Predicciones

La IA enumera hipótesis sobre qué podría estar causando el error antes de investigar.

2

Investigación → causa raíz

Verifica cada hipótesis y llega al origen real del problema.

3

Instrucciones paso a paso

Entrega la solución detallada, en orden y lista para aplicar.

ultimate-debugger-prompt.md

plantilla XML de depuración · open source

⬇️ Descargar prompt
uso rápido
<debug>
  <erro>[cole a mensagem de erro]</erro>
  <contexto>[o que você estava fazendo]</contexto>
  <tarefa>Liste predições, investigue, ache a causa-raiz e me dê
  instruções passo a passo para corrigir.</tarefa>
</debug>

🔌 Configuración de MCP

O Configuración de MCP es una configuración lista de servidores MCP — n8n, Notion, Pinecone, Supabase, Vercel y Fireflies — con placeholders de clave. Es lo que conecta tu agente con herramientas externas.

MCPPara qué
n8nactivar y leer automatizaciones
Notionleer/escribir en páginas y bases
Pineconebúsqueda vectorial / memoria
Supabasebase de datos y autenticación
Verceldeploy y dominios
Firefliestranscripciones de reuniones

🔑 Cuidado con las claves

El archivo viene con placeholders (p. ej.: SUA_CHAVE_AQUI). Sustitúyelos por tus valores y nunca subas claves reales a repositorios públicos.

mcp-config.json

6 MCPs con marcadores de posición para claves

uso rápido

onde colar a configuração e onde substituir a chave (placeholder).
Depois, confirme que a conexão está funcionando.

✅ Lista de verificación QA Pre-Flight

O Lista de verificación de QA preflight es un protocolo de QA y pruebas de estrés por fases, que clasifica cada hallazgo en tres niveles de gravedad — Crítico, Aviso e OK. Es tu verificación antes de "despegar" (publicar).

🔴 Crítico

bloquea el uso · no se puede publicar

🟡 Aviso

funciona, pero mejora con el tiempo

🟢 OK

pasó la prueba

qa-pre-flight-checklist.md

QA por fases · Crítico/Aviso/OK

⬇️ Descargar lista de verificación
uso rápido
Ejecuta QA Pre-Flight Checklist en este proyecto. Haz la prueba de estrés por fases
y clasifica cada hallazgo como Crítico, Advertencia o OK. Enumera primero los
Críticos y di si puedo publicar.

🔬 Ejemplo práctico

Pongamos la biblioteca en marcha: descarga la Cloning Skill y úsala para cambiar el nicho de una plantilla que ya tengas.

  1. Descarga cloning-protocol.md en el tema 1.
  2. Apunta la skill a una plantilla tuya validada.
  3. Pide que lo vuelva a marcar para un nuevo nicho (p. ej., de «clínica» a «gimnasio»): logo, textos, precios, reseñas y color.
  4. Comprueba que la estructura haya quedado intacta y que solo haya cambiado la marca.

En minutos tienes lista una segunda versión: ese es el poder de reutilizar artefactos de la biblioteca.

🏋️ Ejercicio

Elección 1 skill de esta biblioteca y adáptala a tu proyecto:

  1. Descarga el artefacto (skill, config o prompt).
  2. Edítalo según tu contexto: cambia los marcadores de posición, los nichos, los comandos o los criterios.
  3. Guarda la tu versión con un nombre propio y una prueba en el proyecto.

Consejo: empieza por claude.md (tema 5); sirve de base para todas las demás etapas de CODA.
